### ③ ターミナルとエディターとは（初心者向け）

本講義では **2 つの道具** を組み合わせて使います。プログラミング未経験でも、役割を押さえれば問題ありません。

> [!NOTE]
> **前提：フォルダ（＝ディレクトリ）とは** — ファイルをまとめて入れておく「入れ物」です（フォルダの中にフォルダを入れる“入れ子”もできます）。本資料では「フォルダ」と「ディレクトリ」を**同じ意味**で使います。Claude Code は **開いたフォルダ 1 つ＝ひとつの作業場所（プロジェクト）** として扱い、その中のファイルを読み書きします。

#### エディターとは

**エディター**は、PC 上のファイルを開いて読み書きするためのアプリです。メモ帳の高機能版のイメージです。

| 用語 | 意味 |
|---|---|
| フォルダを開く | 講義用の作業場所（プロジェクト）をエディターに読み込む |
| サイドバー（左） | フォルダ内のファイル一覧。Claude が編集したファイル（例: `自己紹介.md`）がここに現れる |
| 編集エリア（中央） | 選んだファイルの中身を表示・編集する |
| 保存 | 変更をディスクに書き込む（多くの場合は自動保存） |

講義で使う VS Code / Cursor / Antigravity IDE は、いずれも **エディター + 内蔵ターミナル** が一体になったツールです。別々のアプリを行き来する必要はありません。

#### ターミナルとは

**ターミナル**は、文字（コマンド）で PC に指示を出す画面です。黒や濃い色の画面に白い文字が並ぶイメージです。

| 用語 | 意味 |
|---|---|
| プロンプト | 入力待ちの行。末尾に `$` や `%`、フォルダ名などが表示される |
| コマンド | 実行したい指示。Enter キーで送信する |
| 出力 | コマンドの結果がその下に表示される |

本講義では、**エディター下部の「ターミナル」パネル** から操作します。

| OS | エディターでターミナルを開く |
|---|---|
| Mac | メニュー「表示」→「ターミナル」、または `` Ctrl + ` `` |
| Windows | メニュー「表示」→「ターミナル」、または `` Ctrl + ` `` |

#### 本講義での役割分担

![エディター、ターミナル、Claude Code が同じフォルダを使い、ターミナルから指示して Claude Code がファイル作成や編集を行う役割分担](/assets/images/training/prep/editor-terminal-claude-roles.png)

| 道具 | あなたがすること | Claude Code との関係 |
|---|---|---|
| **エディター** | フォルダを開く、作られたファイルを開いて内容を確認する | 変更結果を**目で見て確認**する場所 |
| **ターミナル** | `claude` を起動し、日本語で依頼文を入力する | Claude Code と**会話する**場所 |

> [!TIP]
> コマンドは講義資料のとおり **コピー＆ペースト** で始めて構いません。最初から全部入力する必要はありません。貼り付けたら **Enter** を押すのを忘れないでください。

#### 初回の開き方（確認用）

1. エディターを起動する
2. メニューから **フォルダを開く**（講義用フォルダ、または空の新規フォルダ）
3. **ターミナル**パネルを表示する（`` Ctrl + ` ``）
4. ターミナルに `claude` と入力して Enter
5. 初回だけ、配色（テーマ）の選択や注意事項の確認が出るので Enter で進む
6. 「**Quick safety check: Is this a project you created or one you trust?**」（このフォルダを信頼しますか）と聞かれたら、`↓` キーで **`Yes, I trust this folder`** を選んで Enter
7. Claude から返事が来たら準備完了

> [!WARNING]
> 手順 6 の確認画面は、最初から **`No, exit`（終了する）** が選ばれた状態で表示されます。そのまま Enter を押すと Claude Code が終了してしまうので、必ず `Yes, I trust this folder` に切り替えてから Enter を押してください（新しいフォルダで初めて起動するたびに聞かれます）。

## Session 1 — AIエージェントとは？従来のAIとの違い

**このセッションのゴール** AI エージェントの概念と、従来のチャット型 AI との違いを理解する

### 1. AI は「答える」から「動く」へ

2026 年頃から、AI の役割は大きく変わりつつあります。以前は **質問に答える** ことが中心でしたが、いまは **目標に向かって自律的に動く** ことが当たり前になりつつあります。

| 時期 | イメージ | できること | 人間の役割 |
|---|---|---|---|
| 〜2025（答える AI） | 対話型 AI | 質問に対して回答を返す。テキスト生成が中心 | **実行は人間**が担う |
| 2026〜（動く AI） | AI エージェント | 目標を伝えるだけで、データ収集 → 計画 → 実行 → 検証 → 改善を自律的に進める | **重要箇所の承認**に集中する |

> [!NOTE]
> 「動く」とは、人間がコピペや手作業で全部やるのではなく、AI がファイル操作・コマンド実行・外部ツール連携まで **作業の連鎖** を進めることを指します。本講義の Session 2 以降で触れる Claude Code は、この「動く AI」の代表例です。

![従来型の答えるAIと、計画・実行・検証まで進める動くAIの違い](/assets/images/training/session1/answering-ai-vs-agentic-ai.png)

### 2. 従来型 AI（普通の AI）とは

**ChatGPT・Claude（ブラウザのチャット）** など、いわゆる **対話型 AI** を指します。

#### 特徴

- 1 問 1 答で回答を返す
- テキスト生成が主な役割
- ツールは基本的に使わない（または限定的）
- **実装・実行は人間**が行う

例 「議事録の要約テンプレートを書いて」と依頼 → AI が文章を返す → **コピーしてドキュメントに貼る・整形するのは自分**

#### 具体例で比べる（同じ依頼をしたとき）

「新規事業の案を考えて」と頼んだときの違いです。

| 誰がやるか | 従来型 AI | AI エージェント |
|---|---|---|
| 資料の準備 | **人間**がフォルダからファイルを探し、アップロードする | AI が指定フォルダや URL から集める |
| やり取り | **人間**が追加質問（業界・予算・ターゲットなど）に答える | 目的を伝えたあとは AI が進める |
| 成果物の保存 | **人間**がダウンロードして、決めた場所に保存する | AI がファイル作成・保存まで行う |

従来型 AI は **「答えをもらう」** ところまで。あとは人間の手作業が残ります。

### 3. AI エージェントとは

**目的に合わせて、自分で考えて、自分で行動する AI** です。一度 **目標** を伝えれば、その達成に必要な作業を AI が考えて実行します。本講義で扱う **Claude Code** もこのカテゴリに入ります。

#### 特徴

- 目標を伝えるだけで、計画から実行まで進める
- データ収集 → 計画（Plan）→ 実行（Do）→ 検証（Check）→ 改善（Action）を **自律的に反復** する（いわゆる PDCA を自ら回す）
- ファイル操作・コマンド実行・外部サービス連携など、さまざまな **道具（ツール）** を使い分ける
- 重要な操作だけ **人間が承認** する（要所では人が確認・許可する）

#### 動作イメージ

![AIエージェントがデータ収集、計画、実行、検証、改善を繰り返しながら成果物を作る流れ](/assets/images/training/session1/agent-plan-execute-verify-loop.png)

例 「`議事メモ.txt` を読んで要約を `議事録サマリー.md` に書いて」と依頼 → AI がファイルを読み、要約を書き、保存まで行う → 人間は **結果を確認** する

### 4. 4 つの観点で整理する

「答える」ことと「動く」ことは、根本的に設計が異なります。

| 観点 | 従来型 AI（普通の AI） | AI エージェント |
|---|---|---|
| **入力** | 1 問 1 答の質問 | 目標・ゴール |
| **動作** | 回答を返す | データ収集 → 計画 → 実行 → 検証 → 改善 |
| **ツール** | なし／限定的 | ファイル操作・コマンド実行・外部サービス連携など |
| **人間の役割** | 都度、細かく指示する | 最終承認・境界の設計に集中する |

> [!TIP]
> 覚え方のたとえ 従来型 AI は **賢い検索エンジン**（知りたいことを教えてくれる）、AI エージェントは **優秀な部下**（目的を伝えれば自分で動いて仕上げる）に近い。Session 2 の Claude Code は、この「部下」側。任せ方が変わるので、プロンプトの書き方だけでなく **何を任せ、どこで止めるか** の設計が重要になる（許可ダイアログや安全ルールとつながる）。

### 5. 本講義とのつながり

| この Session で学ぶこと | 次の Session でやること |
|---|---|
| 普通の AI と AI エージェントの違い | Claude Code の起動・ファイル操作・Skills |
| 「動く AI」の考え方 | 同梱ファイルの編集・要約・`CLAUDE.md` 追記を実践する |
| 人間は承認・検証に集中 | 許可ダイアログ、`CLAUDE.md`、個人利用の安全ルール |

Session 2 に入る前に、**「文章をもらう AI」ではなく「作業を進める AI」** として Claude Code を捉えておいてください。

## Session 2 — Claude Code の基礎・基本操作と設定

**このセッションのゴール** Claude Code の概要、安全な使い方、ファイル操作、各種コマンド、Skills、コンテキスト管理を理解する（Hooks は概要紹介にとどめる）。

> [!IMPORTANT]
> - **本講義は Claude Code の CLI（ターミナル版）を前提** に進めます。**エディター**でファイルを確認しながら、**ターミナル**（エディター内蔵で可）で指示を出します。
> - `claude` の起動と初回の会話は **事前準備** で済ませてください。

### 1. Claude Code とは

Claude Code は、あなたの PC 上のプロジェクトを相手に、ファイルの読み書きやコマンド実行まで行う **AI エージェント** です。普通のチャット AI が「文章で答える」ことを中心にするのに対し、Claude Code は作業を進めながら結果をファイルやコマンド出力として残します。

#### 本講義の前提 — CLI（ターミナル版）で進める

Anthropic は同じエンジンを、用途に応じて複数の画面で提供しています（[Platforms 公式ドキュメント](https://code.claude.com/docs/ja/platforms)）。

| 形態 | 操作のイメージ | 主な用途 |
|---|---|---|
| **CLI（本講義で使用）** | ターミナルで `claude` と入力 | ターミナル作業、定型処理の自動化、プラグイン。機能が最も揃っている |
| **Desktop アプリ** | macOS / Windows の専用アプリ | 変更箇所を見比べる確認、複数の作業を並行、画面操作（マウス中心） |
| **VS Code / Cursor 拡張** | エディター内の Claude Code | 変更前後をエディター上で見比べながらの作業 |
| **JetBrains 拡張** | IntelliJ・PyCharm など JetBrains 製 IDE 内 | JetBrains の IDE を使っている人向け |
| **Web / モバイル** | ブラウザや Claude アプリ | クラウドで継続実行、離席中の依頼・監視など。手元の CLI セッションをスマホから操作する **Remote Control** もある |

本講義では **CLI** を使います。理由は次のとおりです。

- 事前準備でインストールした **`claude` コマンド** が CLI 版である
- **Skills や `.claude/`** など、設定をファイルで育てる流れが CLI ワークフローと一致する

> [!NOTE]
> Desktop アプリを普段から使っていても構いません。Desktop と CLI は **同じエンジン** で、同じプロジェクトなら `CLAUDE.md` や `.claude/` の設定を共有できます。違いは主に **操作画面**（ターミナルか GUI か）です。講義中は手順どおりターミナル版で操作し、講義後に Desktop へ移しても学んだ設定は活かせます。

公式の目安 **並列セッションや視覚的なレビュー** には Desktop、**スクリプト・自動化・ターミナル作業** には CLI（[Desktop ドキュメント](https://code.claude.com/docs/ja/desktop)）。

### 2. 個人利用の安全ルール

Claude Code はお手元の PC 上で動作しますが、入力した文章と AI の応答は Anthropic のサーバーを経由します（[セキュリティ](https://code.claude.com/docs/ja/security) / [プライバシーポリシー](https://www.anthropic.com/legal/privacy)）。便利さより先に、何を入力してよいかの境界線を決めます。

#### 入力してよい情報

- 講義用のダミーデータ（`講義サンプル` フォルダ内のファイル）
- 公開済み情報
- 個人名や会社名を伏せた業務例
- 自分で外部 AI 利用を許可している文書

#### 入力して避けるべき情報

> [!CAUTION]
> 以下の情報は、原則として外部 AI へ送信しないでください。

- 他人の個人情報（本人の同意なく）
- クライアント名、契約金額、未公開案件
- パスワード、API キー、アクセストークン
- 勤務先で外部 AI 利用が禁止されている機密資料

#### ダミーデータ化の例

| 元データ | 置き換え例 |
|---|---|
| 株式会社ABC | クライアントA |
| 田中太郎 | 担当者A |
| 1,250万円 | 約1,000万円 |
| 新製品Xの未公開価格 | 新サービスの価格 |

#### 情報の流れ

![Claude Code に入力してよいダミーデータと、外部 AI に入力してはいけない機密情報の境界](/assets/images/training/session2/safe-input-boundary.png)

### 3. 権限モードと許可ダイアログ

Claude Code には、**どこまで確認なしで動いてよいか** を決める「権限モード」があります（[権限モード公式ドキュメント](https://code.claude.com/docs/ja/permission-modes)）。画面下部（入力欄の下）に現在のモードが表示され、**`Shift + Tab`** で切り替えられます。

| モード（画面表示） | 確認なしで動くもの | 向いている場面 |
|---|---|---|
| **Manual**（`⏸ manual mode on`） | 読み取りだけ。編集・コマンド実行は毎回確認する | 慣れないうち、重要なファイルを扱うとき（**本講義はこれ**） |
| **Accept edits**（`⏵⏵ accept edits on`） | ファイル編集と基本的なファイル操作 | 編集結果をあとからまとめて確認したいとき |
| **Plan**（`⏸ plan mode on`） | 読み取り・調査のみ。編集は計画の承認後 | 大きな作業の前に計画を立てさせたいとき（→ §9） |
| **Auto**（`⏵⏵ auto mode on`） | ほぼすべて。別の AI（分類器）が裏で危険な操作をチェックしてブロックする | 方向性を信頼できる長めの作業 |

> [!IMPORTANT]
> **2026 年のアップデートで、普通のフォルダで `claude` を起動すると「Auto（自動）モード」で始まるようになりました**（v2.1.283 以降）。Auto モードでは、ファイル編集などで許可ダイアログが **ほとんど出ません**。
>
> 本講義で使う **`講義サンプル` フォルダは、設定ファイル（§8）で Manual モードから始まるようにしてあります**。許可ダイアログを見ながら、1 つずつ確認して進める体験をしてください。

#### 許可ダイアログ

Manual モードでは、Claude Code がファイル編集やコマンド実行を行う前に、次のような許可ダイアログが出ます。

![Claude Code の許可ダイアログ。自己紹介.md の変更前後の差分の下に「Do you want to make this edit to 自己紹介.md?」と表示され、1. Yes / 2. Yes, and switch to accept edits for this session / 3. No の 3 択が並ぶ](/assets/images/training/session2/permission-dialog.png)

画面には **変更前（赤）と変更後（緑）の差分** が表示されるので、何が書き換わるかを確認してから選びます（上の画像は §14 の依頼をしたときの実際の画面です）。

| 選択肢 | 意味 | この段階での目安 |
|---|---|---|
| `Yes` | 今回だけ許可 | 基本はこれ |
| `Yes, and switch to accept edits (...) for this session` | このセッションの間だけ Accept edits モードに切り替え、以後のファイル編集と基本的なファイル操作を確認なしで許可（終了するとリセット。`Shift + Tab` と同じ） | 頻出操作だけ慣れてから検討 |
| `No` | 拒否（`Tab` でコメントを付けて、別のやり方を指示することもできる） | 意図しない操作なら選ぶ |

コマンド実行のダイアログでは、`Yes, and don't ask again`（このコマンドは次回以降も聞かない）や `Yes, and switch to auto mode`（許可して Auto モードに切り替える）が出ることもあります。**講義中はどちらも選ばず、`Yes` か `No` を選んでください。**

初回は、基本的に `Yes` を選びます。意味が分からない操作が出たら、許可せず質問してください。

> [!NOTE]
> Auto モードは便利ですが、公式ドキュメントでも「**安全を保証するものではない**」と明記されています。慣れるまでは Manual モードで「Claude が何をしようとしているか」を目で確認する習慣をつけましょう。普段のフォルダでも Manual で始めたい場合は、`claude --permission-mode manual` で起動するか、起動後に `Shift + Tab` を 1 回押します。

### 4. 止め方を覚える

AI を安全に使うために、始め方より先に止め方を覚えます。

| 操作 | 使う場面 |
|---|---|
| `Esc` | 実行中の作業を止めたい（それまでの作業は残る）。許可ダイアログで押すと `No` と同じ |
| `Esc` 2 回（入力欄が空のとき） | 巻き戻しメニューを開いて、以前の状態に戻したい（`/rewind` と同じ） |
| `/exit` | セッションを終了したい |

> [!TIP]
> 入力欄に文字が入っている状態で `Esc` を 2 回押すと、入力中の文字が消えるだけです（`↑` キーで呼び戻せます）。巻き戻しをしたいときは、入力欄を空にしてから押してください。

### 5. チェックポイント

Claude Code は、**あなたがプロンプト（依頼文）を送るたびに** その時点のファイルの状態を **チェックポイント** として記録します（[チェックポイント公式ドキュメント](https://code.claude.com/docs/ja/checkpointing)）。§4 で覚えた `Esc` 2 回（または `/rewind`）で巻き戻しメニューを開き、戻したい時点を選びます。

| メニューの選択肢 | 動作 |
|---|---|
| Restore code and conversation | ファイルと会話の両方をその時点に戻す |
| Restore conversation | 会話だけ戻す（ファイルは今のまま） |
| Restore code | ファイルだけ戻す（会話は今のまま） |
| Summarize from here / up to here | その時点以降／以前の会話を要約してコンテキストを空ける（→ §13） |
| Never mind | 何もせずに戻る |

ポイント

- ファイル編集の失敗を戻したい時に使う
- セッションを終了しても、`/resume` で再開すれば巻き戻せる（スナップショットは約 30 日で自動削除）
- **戻せないもの** — 外部システムへの操作や送信済みの内容、Claude がコマンド（Bash など）だけで変更したファイル
- 重要なファイルを扱う時は、作業前にコピーを残しておく（Git などのバージョン管理が確実）

### 6. CLAUDE.md — プロジェクトのメモリ

#### そもそも「メモリ」とは

Claude Code は、セッション（ターミナルを開いてから閉じるまでの一連の会話）が変わるたびに **記憶がまっさらな状態** で始まります。前回「日本語で答えて」と伝えても、次のセッションでは忘れています。この **「セッションをまたいで覚えておいてほしいこと」を書き留めておく仕組み** が「メモリ」です。

![新しいセッションはまっさらな状態で始まり、メモリに書き留めた CLAUDE.md や自動メモリが次のセッションで読み込まれる流れ](/assets/images/training/session2/memory-concept-flow.png)

メモリには2種類あります。

| 種類 | 書く人 | 何が書かれるか |
|---|---|---|
| **CLAUDE.md** | あなた（人） | ルールや前提。起動時に毎回読み込まれる |
| **自動メモリ** | **Claude 自身** | あなたの訂正や好みを Claude が学習して自動保存（標準でオン）。`/memory` で確認・編集・オンオフの切り替えができる |

> [!TIP]
> まずは「人が書く CLAUDE.md」を押さえれば十分です。自動メモリは Claude が裏側で勝手に育てていくもの、という理解で OK です。本 §6 で扱うのは CLAUDE.md です。
>
> 会話の中で「**〇〇を覚えておいて**」と頼むと自動メモリに、「**〇〇を CLAUDE.md に追記して**」と頼むと CLAUDE.md に書き込まれます。

CLAUDE.md は、Claude Code に対する永続的な指示書です。プロジェクトのルートに置くと、起動時に自動で読み込まれます。

```markdown
# プロジェクトルール

- 常に日本語で応答してください
- 報告書は「ですます調」で作成してください
- 機密情報をファイル名に含めないでください
- 不明点がある場合は、作業前に確認してください
```

ポイント

- 抽象的な精神論より、具体的で検証可能な指示を書く
- 長すぎると毎回の読み込み負荷になるため、200 行以内を目安にする
- 200 行を超えそうなら `.claude/rules/` に用途別で分割する
- 特定フォルダだけに効かせるルールは `paths` で対象を限定できる（触っていないときはコンテキストに載らない）

> [!NOTE]
> **`.claude/rules/` とは** — CLAUDE.md を1ファイルに詰め込む代わりに、`testing.md`・`security.md` のようにテーマ別の `.md` ファイルに分けて置くためのフォルダです（`プロジェクト/.claude/rules/` に作成）。各ファイルの先頭に `paths`（対象ファイルのパターン）を書くと、**その種類のファイルを触ったときだけ**ルールが読み込まれ、普段はコンテキストを消費しません。`paths` を書かないルールは CLAUDE.md と同じく毎回読み込まれます。

#### CLAUDE.md のスコープ

| スコープ | 場所 | 範囲 |
|---|---|---|
| このプロジェクト | `./CLAUDE.md`（または `./.claude/CLAUDE.md`） | このプロジェクトのみ |
| 全プロジェクト共通 | `~/.claude/CLAUDE.md` | 自分の全プロジェクト |

> [!NOTE]
> `./CLAUDE.local.md` という個人専用のファイルもありますが、これは「チームと共有したくない個人ルール」を分けるための仕組みです。設定を共有しない個人利用では `./CLAUDE.md` にまとめて問題ありません。

> [!NOTE]
> **`AGENTS.md` について** — Cursor など他の AI ツール向けに `AGENTS.md` を置いているフォルダでは、`CLAUDE.md` が無ければ Claude Code が `AGENTS.md` を代わりに読み込みます（v2.1.277 以降）。両方ある場合は `CLAUDE.md` が優先されます。読み込まれたファイルは `/context` の **Memory files** 欄で確認できます。

#### CLAUDE.md を書くときのアンチパターン

よく起きる「効かない・逆効果」な書き方と改善例です。

| 書きがちな例 | 問題 | 改善 |
|---|---|---|
| 「丁寧に対応してください」 | 曖昧で検証できない | 「見出しは体言止め、本文はです・ます調で書く」 |
| 「重要な情報は守ってください」 | Claude に何が重要かを委ねている | 送信してはいけない情報を具体的に列挙する |
| 業務マニュアルを丸ごと CLAUDE.md に貼り付ける | 長すぎてコンテキストを圧迫する | `.claude/rules/` に用途別で分割し、必要なときだけ読み込ませる。手順書は Skill（§11）にする |
| 「状況に応じて判断してください」 | 曖昧な指示は常にデフォルト動作になる | 「判断が必要な場合は、作業前に確認してください」と明示する |

> [!TIP]
> CLAUDE.md やルールが増えてきたら、`/doctor prompt-audit` を実行すると、古くなった指示や矛盾している指示を Claude が洗い出して修正案を出してくれます（勝手には書き換えません）。

#### サンプルフォルダの `CLAUDE.md` を確認する

エディターで **ルートの `CLAUDE.md`** を開き、中身をざっと読みます。続けて Claude に次を依頼します。

```text
このプロジェクトの CLAUDE.md に書かれているルールを3つ、箇条書きで要約してください。
```

完了の目安

- エディターで `CLAUDE.md` の実物を開けている
- Claude がルールを要約して返す（起動時の自動読み込みを体験）

> [!NOTE]
> **ルールの追記実習**は **§16** で行います（ゼロから作るのではなく、既存の `CLAUDE.md` に 1 行足す）。

### 7. プロジェクトルートと `.claude/` ディレクトリ

Claude Code の設定は、**プロジェクトルート**と **`.claude/` 配下**に置きます。講義用サンプルでは次の構成です。

```text
講義サンプル/                  # 本講義の作業フォルダ（§5 のあとで準備）
├── 説明書.md                  # サンプルの説明（最初に読む）
├── CLAUDE.md                  # 共有ルール
├── 自己紹介.md                # §14 用（穴埋めテンプレート・差し替え演習）
├── 議事メモ.txt               # §15 用のダミー議事メモ
└── .claude/
    ├── settings.json          # 権限・フックなど
    └── skills/
        └── meeting-summary/
            └── SKILL.md       # §11 で参照
```

> [!TIP]
> **`.claude` がフォルダ一覧に見えない**ときは、OS とエディターの両方を確認してください。
> - **Mac**：Finder では `Cmd + Shift + .` で隠しファイルの表示を切り替えられます。
> - **Windows**：エクスプローラーの「表示」タブ →「表示」メニュー →「隠しファイル」にチェック（Win10 では「表示」タブ直下の場合もあります）。
> - **VS Code / Cursor**：設定（Mac は `Cmd + ,`、Windows は `Ctrl + ,`）で `files.exclude` を検索し、`.claude` に該当するパターンを削除すると表示されます。

### 8. お願いとガード（CLAUDE.md / settings / hooks）

| 書く場所 | 強制力 | 特徴 | 代表的な使い方 |
|---|---|---|---|
| **CLAUDE.md** | 弱い | Claude が毎セッション最初に読む「行動指針」。努力して守るが絶対ではない | 「報告書は常に日本語で」「命名規則は〜」 |
| **settings.json** | 中〜強 | 権限設定全般。許可・拒否のハードルールを定義する | 危険なコマンドの拒否、許可リスト |
| **hooks** | 非常に強い | 特定イベント発生時に**自動実行**される仕組み。ブロックも可能 | 危険操作の前に自動停止、編集後に自動フォーマット |

![CLAUDE.md、settings.json、hooks の順に強制力が強くなる設定レイヤー](/assets/images/training/session2/config-strength-stack.png)

`CLAUDE.md` は「ソフトなお願い」、`settings.json` は「ハードルール（権限設定）」と覚えると整理しやすいです。同じ内容を両方に書く必要はありません。コンテキストが長くなると `CLAUDE.md` の内容は無視されることがある点に注意してください。

**hooks（フック）** が最も強力です。`PreToolUse` フックを使うとツール実行の直前にチェックを入れ、危険なら自動でブロックできます。

> [!NOTE]
> hooks の設定にはやや技術的な知識が必要です。初心者のうちは「こういう仕組みがある」と知っておくだけで十分で、この講義で実際に設定する必要はありません。

サンプルフォルダの **`.claude/settings.json`** をエディターで開き、中身を確認します（講義では触らず「ここに権限設定を書く場所」と理解するだけで十分です）。

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "defaultMode": "default"
  }
}
```

`"defaultMode": "default"` は「**このフォルダでは Manual モード（毎回確認）で起動する**」という設定です（§3）。これが 1 行入っているので、`講義サンプル` では許可ダイアログを見ながら進められます。

> [!NOTE]
> 1 行目の `"$schema": "..."` は、**エディターが入力補完や設定ミスの警告を出すための補助**です。Claude Code の動作には必須ではありません（消しても動きます）。なお `settings.json` は**コメントを書けない形式**なので、メモはこのファイル外（README など）に残します。

#### 設定の優先順位

| 強い ← → 弱い | 内容 |
|---|---|
| 組織の管理設定（managed settings） | 会社の IT 部門などが配布する設定。個人では上書きできない |
| 起動時の CLI オプション（`--settings` など） | そのセッションだけの一時的な上書き |
| `.claude/settings.local.json` | このプロジェクトの個人用設定 |
| `.claude/settings.json` | このプロジェクト |
| `~/.claude/settings.json` | 全プロジェクト共通 |

> [!NOTE]
> コマンド実行の許可ダイアログで「次回以降も聞かない（`Yes, and don't ask again`）」を選ぶと、`.claude/settings.local.json` という個人用のファイルが自動で作られます。チームで設定を共有しない個人利用では `settings.json` との違いを気にする必要はありません。`.claude/` の中に増えていても問題ないファイルです。許可ルールの一覧は `/permissions` で確認・削除できます。

### 9. Plan モード

大きな作業を任せる時は、いきなり編集させず、まず計画だけ作らせます。

| 方法 | 操作 |
|---|---|
| キーボード | プロンプト欄で `Shift + Tab` を押し、画面下部が `⏸ plan mode on` になるまで切り替える |
| 単発指示 | プロンプトの先頭に `/plan`（例: `/plan 議事メモを整理する手順を考えて`） |
| 起動時 | `claude --permission-mode plan` |

`Shift + Tab` を押すたびに **Manual → Accept edits → Plan →（Auto）→ Manual…** の順で切り替わります。`講義サンプル`（Manual で起動）なら **2 回**、Auto で起動した普通のフォルダなら **3 回** で Plan モードになります。

Plan モードでは、読み取りと調査だけを行い、計画を提示します。計画ができると、次のどれで進めるかを聞かれます。

| 選択肢 | 意味 |
|---|---|
| `Yes, and use auto mode` | 計画を承認し、Auto モードで一気に実行する |
| `Yes, manually approve edits` | 計画を承認し、編集は 1 つずつ確認しながら進める（**講義ではこれ**） |
| `No, keep planning` | 承認せず、計画の修正を指示する |

慣れるまでは、大きな作業は Plan モードで始めると安全です。

### 10. プロンプト技法と反復

Claude Code では「一度の指示で完璧な結果を出す」より、**確認しながら段階的に進める**ほうが確実です。

#### 2 段階パターン — 確認してから動かす

Plan モード（§9）と組み合わせ、編集の前に内容を確認します。

```text
まず「何を変更するか」だけ教えてください。まだ編集しないでください。
```

内容を確認したら、続けて

```text
問題なければ進めてください。
```

#### 指示の書き方の原則

| 原則 | 悪い例 | 良い例 |
|---|---|---|
| **具体的に** | 「よくしてください」 | 「見出しを箇条書きに変えてください」 |
| **1 回 1 タスク** | 「全部整理して」 | 「まず `議事メモ.txt` だけを要約してください」 |
| **対象を明示** | 「保存して」 | 「`議事録サマリー.md` として保存してください」 |

#### 期待と違ったときの戻し方

| 状況 | 対応 |
|---|---|
| 一部だけ直したい | 「〇〇の部分だけ、〜に変えてください」と追加指示する |
| やり直したい | `Esc` 2 回でチェックポイントに戻してから再依頼する |
| 最初からやり直したい | `/clear` でリセットし、より具体的な指示で再開する |

> [!TIP]
> うまくいかないときは「指示が足りなかった箇所」を特定して次の依頼に活かすのが上達の近道です。同じ失敗を繰り返すなら、その指示を `CLAUDE.md` に追記することを検討してください。

### 11. Skills / Commands / Hooks

| 部品 | 役割 | 使いどころ |
|---|---|---|
| Skills | 手順・知識のパッケージ（`.claude/skills/各フォルダ/SKILL.md`）。**新規はこちらを推奨** | 議事録整理、資料レビューなど |
| Commands | 旧形式の定型プロンプト（`.claude/commands/*.md`）。**現在は Skills に統合済み**（既存ファイルはそのまま動く） | `/review` のような 1 行コマンド |
| Hooks | 「〇〇したら自動で△△する」を決めておく | 危険な操作をしようとしたら自動で止める、作業が終わったら音で知らせる |

> [!NOTE]
> 以前は「Commands」と「Skills」は別物でしたが、現在は **カスタムコマンドが Skills に統合** されました（[Skills 公式ドキュメント](https://code.claude.com/docs/ja/skills)）。`.claude/commands/deploy.md` と `.claude/skills/deploy/SKILL.md` は、どちらも `/deploy` として同じように動きます。これから作るなら Skills を選べば OK です。使える Skill の一覧は **`/skills`** で確認できます。
>
> Claude Code には最初から入っている **組み込み Skill** もあります（例: 設定の不具合を診断する `/doctor`、定期実行する `/loop` など）。

初回導入では、まず CLAUDE.md から始め、定型手順が必要になったら Skills を追加します。Hooks は「〇〇したら自動で△△する」を決めておく仕組みですが、設定にはやや技術的な知識が必要なので、初心者のうちは「こういう仕組みがある」と知っておくだけで十分です。運用が増えてから段階的に導入します（設定済みの Hooks は `/hooks` で確認できます）。

#### メモリ（CLAUDE.md）と Skill の違い

「どっちに書けばいいの？」と迷いやすいので整理します。

| | メモリ（CLAUDE.md） | Skill |
|---|---|---|
| 読み込まれるタイミング | **毎回**（起動時に常時） | **必要なときだけ**（内容が合致 or 名前を指定したとき） |
| 中身 | ルール・前提・常に守ること | 手順（ステップ）・知識のパッケージ |
| 向くもの | 「常に日本語で」のような短い方針 | 「議事録の作り方」のような定型作業 |
| コンテキスト | 常に消費する | 使うときだけ消費（普段は節約になる） |

> [!TIP]
> **常に守らせたいこと → CLAUDE.md** ／ **手順をなぞらせたい作業 → Skill** と覚えると迷いません。

#### サンプルの Skill を開いて確認する

エディターで次を開きます。

`.claude/skills/meeting-summary/SKILL.md`

先頭の `description` が「いつこの Skill を使うか」の目印です。

> [!NOTE]
> このサンプルには Skill が 2 つ入っています — `meeting-summary`（議事録整理・§15）と `email-draft`（連絡メールの下書き・§17B）。ここではまず `meeting-summary` を開いて確認します。

> [!NOTE]
> **Skill が読み込まれる仕組み** — Claude は、あなたのプロンプトの内容が Skill の `description` に合うと判断したら、**自動でその Skill を選んで** 手順を読み込みます（名前を言う必要はありません）。確実に使わせたいときは「meeting-summary Skill を使って」のように **名前を直接指定** することもできます。

続けて Claude に次を依頼します。

```text
meeting-summary という Skill の SKILL.md を読んで、
この Skill が何をするものか、いつ使うべきかを2文で説明してください。
まだ議事メモ.txt は編集しないでください。
```

完了の目安

- Skill ファイルの実物を開けている
- Claude が Skill の目的を説明できる

### 12. MCP（Model Context Protocol）

**MCP（Model Context Protocol）** は、Claude Code と外部ツール・サービスをつなぐための共通のつなぎ方（標準ルール）です。通常の Claude Code は手元のファイルやターミナルを操作できますが、MCP サーバーを追加することで、Slack・カレンダー・Google Drive など外部サービスの情報取得や操作もできるようになります。

#### 仕組みのイメージ

![Claude Code と外部ツールの間に MCP サーバーが入り、通訳・ブリッジとしてチャット、カレンダー、ファイルなどのサービスへつなぐ流れ](/assets/images/training/session2/mcp-bridge-flow.png)

「Slack の #連絡 チャンネルを見て」と指示したとき、MCP サーバーが Slack API を叩いて結果を返します。Claude Code 側は API の仕様を知らなくてよく、MCP サーバーがすべて取り回します。

#### 代表的な MCP サーバーの例

| カテゴリ | サーバー例 | できること |
|---|---|---|
| コミュニケーション | Slack MCP | チャンネル読み取り、メッセージ送信 |
| カレンダー | Google Calendar MCP | 予定の参照・作成 |
| ドキュメント | Notion MCP | ページの検索・作成・更新 |
| クラウドストレージ | Google Drive MCP | ファイルの検索・読み取り |
| Web 検索 | Brave Search MCP | 最新情報の検索・要約 |

Anthropic 公式・コミュニティ製のサーバーがオープンソースで公開されており、自作も可能です。追加した MCP サーバーの接続状況やログイン（認証）は **`/mcp`** で確認・管理できます。

#### Skills / Hooks との違い

| | 役割 | 変えるもの |
|---|---|---|
| CLAUDE.md / Skills / Hooks | Claude の **ふるまい・手順** をカスタマイズ | Claude 自身の動き方 |
| MCP サーバー | Claude が使える **外部ツール** を追加 | アクセスできる情報・操作範囲 |

「Claude をどう動かすか」が Skills / Hooks の世界、「Claude が何に触れるか」を広げるのが MCP です。

### 13. コンテキストウィンドウ

会話履歴、読み込んだファイル、コマンド結果、CLAUDE.md は、すべて**コンテキストウィンドウ**に載ります。作業机の例えで言えば、机の上に載せられる資料の総量です。載せすぎると重要な情報が埋もれ、返答の質が落ちることがあります。

![会話履歴、ファイル、コマンド出力、CLAUDE.md がコンテキストに載り、増えすぎたら compact や clear で整理するイメージ](/assets/images/training/session2/context-window-desk.png)

#### 対処の流れ

長時間の作業で調子が悪くなったときは、次の流れで対応します。

1. **`/context`** で使用量を確認する
2. 状況に応じてどちらかを選ぶ
   - **同じ作業を続ける** → **`/compact`** で会話を要約圧縮する
   - **別の作業に切り替える** → **`/clear`** で会話をリセットする

#### コンパクション（`/compact`）

会話履歴を要約してコンテキストを空け直す操作です。同じ作業を続けるときに使います。

1. `Esc` でタスクを中断
2. `/compact` を実行（`/compact 議事録の作業を中心に残して` のように、残したい内容を指示することもできる）
3. 要約が完了したら作業を再開

`/clear` とは異なり、会話の流れを保ったまま容量だけ圧縮できます。`CLAUDE.md` は圧縮後もファイルから読み込み直されるので、ルールは消えません。

> [!NOTE]
> コンテキストが上限に近づくと、Claude Code は **自動でコンパクションを実行** します（自動コンパクション）。そのため満杯になってもセッションは止まりませんが、自動の要約は「何を残すか」を Claude が判断します。大事な作業の区切りでは、自分で `/compact` に指示を付けて実行するほうが確実です。

#### 会話をリセットする（`/clear`）

別のタスクに切り替えるときは `/clear` を使います。`CLAUDE.md` やプロジェクトの設定ファイルは残ったままです。消した会話も `/resume` で呼び戻せます。

#### セッション再開（`/resume`）

前回のセッションを会話履歴ごと引き継いで再開します。ターミナルを閉じた後でも、前の文脈を復元できます。`/resume` だけを打つと過去のセッション一覧が出るので、選んで再開します（ターミナルから `claude --continue` で直前のセッションを再開することもできます）。

#### 使用率の目安

`/context` で表示される使用率を参考に、以下を目安に動きましょう（公式の基準ではなく、講義としての運用の目安です）。

| 使用率 | 推奨アクション |
|--------|----------------|
| 〜60%  | 様子見（余裕あり） |
| 60〜80% | `/compact` を検討（予防的に圧縮） |
| 80〜90% | `/compact` を強く推奨 |
| 90% 超 | `/compact` または `/clear` で必ず対処（放置すると自動コンパクションが走る） |

> 60〜70% 付近から「重要な情報の失念」が起き始めるケースもあります。気になったら早めに対処するのが安心です。自動コンパクションが始まるタイミングは `/autocompact`（例: `/autocompact 500k`）で早めることもできます。

#### 日常のコツ（予防）

- 長いファイルを一度に読みすぎない
- 会話が長くなったら `/context` で確認し、`/compact` または `/clear` を検討する
- `CLAUDE.md` が長くなったら `.claude/rules/` 分割や `paths` による限定を検討する

#### モデルによるコンテキスト上限

2026 年 10 月時点の最新モデル（Claude 5 世代）は、**いずれも標準で約 1M（100 万）tokens** のコンテキストウィンドウ（机の広さ）を持っています（[モデル設定公式ドキュメント](https://code.claude.com/docs/ja/model-config)）。

| モデル | コンテキスト上限（目安） | 日本語文字数の目安 |
|---|---|---|
| Claude Fable 5.1 | 約 1M tokens | 約 50万〜100万文字（Webページ数百〜数千ページ分） |
| Claude Opus 5.5 | 約 1M tokens | 同上 |
| Claude Sonnet 5.5 | 約 1M tokens | 同上 |
| Claude Haiku 5.5 | 約 1M tokens | 同上 |

机が広くなっても、載せすぎると重要な情報が埋もれる点は同じです。上の「使用率の目安」に沿って整理しましょう。

#### モデルの選び方（`/model`）

ターミナルで `/model` を実行すると、利用中のモデルを切り替えられます。選んだモデルは次回以降の既定になります。

| モデル | 向いている場面 | 速度 |
|---|---|---|
| **Fable 5.1** | 最も高性能。何時間もかかる大きな作業、最難関の依頼 | じっくり（調査・検証を多めに行う） |
| **Opus 5.5** | 複雑な設計、多ファイル改修、判断が難しい依頼。**Pro 以上の初期設定（Default）** | 遅め |
| **Sonnet 5.5** | 日常の大半（要約、下書き、Skills 作成など） | 速め |
| **Haiku 5.5** | 単純な整形、短文生成、定型処理 | 最速 |

迷ったら **初期設定（Opus 5.5）のまま** で構いません。使用量の上限に早く達してしまう場合や、日常的な軽い作業が中心なら **Sonnet**、単純で速さ優先なら **Haiku** に切り替えます。

> [!NOTE]
> **Fable は自動では選ばれません。** 使うときは `/model fable` で明示的に選びます。プランによっては、Fable の利用がプランの使用量枠ではなく **追加の使用クレジット（有料）** から引き落とされる場合があり、そのときは `/model` の一覧に「Requires usage credits」と表示され、使う前に確認画面が出ます。

#### 考える深さ（`/effort`）

モデルとは別に、**どれだけ深く考えさせるか（effort）** も調整できます。`/effort` を実行するとスライダーが開き、`low` → `medium` → `high` → `xhigh` → `max` から選べます（`/model` の画面で左右キーでも変更可）。

- Opus 5.5・Sonnet 5.5・Haiku 5.5 の初期値は **`medium`**
- 深くするほど回答の質は上がりやすい反面、時間と使用量が増える
- 講義中は初期値のままで十分。難しい依頼でうまくいかないときに上げてみる

> [!NOTE]
> 本講義の課金は **Claude Pro プラン以上** のサブスクリプションです。Anthropic 公式のトークン単価表（API 課金）は Claude Code の個人利用とは別の仕組みです。利用量は **`/usage`** でプランの使用量（5 時間・1 週間の枠）を確認できます。常に表示したい場合は **付録 B** のステータスラインも参考にしてください。
>
> モデルの詳細比較は [Anthropic 公式 — モデル概要](https://platform.claude.com/docs/ja/about-claude/models/overview) を参照してください（API 開発者向けの情報が中心です）。

ここまでの操作を、より実務に近い形で 2 つ試します。どちらも `講義サンプル` の既存ファイルだけ・**1 つの依頼文で完了**します。「自分の日常業務にどう使えるか」のイメージがつかめます。

**Part A — AI 秘書（cc-secretary）**（§1〜§7）

### 1. AI 秘書とは

**AI 秘書**（cc-secretary）は、タスク、メモ、予定、振り返りを Claude Code 上で扱うための仕組みです。目的は、単なる TODO 管理ではありません。日々の業務情報をファイルとして残し、後から Claude Code と一緒に整理・改善できる状態にすることです。

Session 2 で学んだファイル操作・CLAUDE.md・Skills の知識を前提に、「自分専用の秘書環境」を立ち上げます。

![素の Claude Code では秘書ワークのフォルダ構成やルールを自分で設計する必要があり、cc-secretary を入れると .secretary にタスク、メモ、アイデア、ミーティング、振り返りが整理される比較](/assets/images/training/session3/cc-secretary-overview.png)

#### 素の Claude Code との違い

素の Claude Code でも「メモを `.md` に書く」「タスクを管理する」ことは可能です。ただし、その場合は **フォルダ構成・命名規則・運用ルールをすべて自分で設計し、CLAUDE.md に書き起こす** 必要があります。cc-secretary は、その「秘書としての型」をプリセットで用意してくれるプラグインです。

| 観点 | 素の Claude Code | cc-secretary を入れた AI 秘書 |
|---|---|---|
| 保存先・フォルダ構成 | 自分で決めて運用する | `.secretary/` 配下を自動生成 |
| カテゴリ（todos / ideas / meetings 等） | 自分で設計する | 14 カテゴリがプリセット |
| 起動・呼び出し | 毎回プロンプトで指示する | `/secretary` コマンドで管理モードへ |
| 運用ルール | 自分で CLAUDE.md に書く | オンボーディングで対話的に生成 |
| 週次レビュー・振り返り | 自分で仕組みを作る | 振り返り導線が組み込み済み |

つまり cc-secretary は、Session 2 で手で作っていた「秘書ワークの土台」を **インストール一発で用意する** ためのプラグインです。手動でも同じことはできるため、ネットワーク制限などで導入できない場合は §7 の手動版 AI 秘書で同等の運用に切り替えられます。

### 2. cc-secretary をインストールする

AI 秘書を使うには、まず cc-secretary プラグインを導入します。Claude Code のプロンプト欄で、1 行ずつ実行します。

```text
/plugin marketplace add Shin-sibainu/cc-secretary
```

続けて

```text
/plugin install secretary@cc-secretary
```

`/plugin install` を実行すると、すぐにはインストールされず、プラグインの **詳細画面** が開きます。プラグインが追加するもの（Skill・コマンドなど）を確認し、インストール先の範囲（スコープ）を選びます。

| 選択肢 | 意味 |
|---|---|
| `Install for you (user scope)` | 自分の PC のすべてのフォルダで使える（**講義ではこれ**） |
| `Install for all collaborators on this repository (project scope)` | このリポジトリで作業する全員に有効 |
| `Install for you, in this repo only (local scope)` | 自分だけ・このフォルダだけで使える |

インストール後のメッセージが「`Plugin is now active.`」ならそのまま使えます。「`Run /reload-plugins to apply.`」と表示された場合は、次を実行します。

```text
/reload-plugins
```

> [!TIP]
> うまく有効にならないときは、いったん `/exit` で終了し、ターミナルで再度 `claude` を起動してください（再起動でも有効化されます）。

> [!NOTE]
> プラグインの Skill は「`/プラグイン名:Skill名`」の形で登録されるため、`/` を打ったときの候補一覧には **`/secretary:secretary`** と表示されます。入力は `/secretary` だけで OK です（Enter を押すと候補の `/secretary:secretary` が実行されます）。

完了の目安

- `/` を打つと候補に `/secretary:secretary` が表示される
- エラーなく AI 秘書（管理モード）が起動する

### 3. AI 秘書でできること

cc-secretary は、Claude Code 上で動く業務秘書プラグインです。対話的なオンボーディングを通じて `.secretary/` フォルダを自動生成し、タスク・メモ・アイデア・週次レビューを一元管理できます。

#### 対応カテゴリ（14 種類）

| カテゴリ名 | 説明 |
|---|---|
| todos | デイリータスク管理 |
| inbox | 思いついたことをすぐ書き留める場所（常に含む） |
| ideas | アイデアの記録 |
| meetings | 議事録 |
| projects | プロジェクト管理 |
| clients | クライアント管理 |
| research | リサーチ・調査 |
| knowledge | ナレッジベース |
| reviews | 週次・月次レビュー（常に含む） |
| content-plan | コンテンツ企画（ブログ/YouTube/SNS） |
| journal | 日記・ジャーナル |
| reading-list | 読書リスト |
| debugging | デバッグログ |
| finances | 財務・経理 |

### 4. オンボーディング

```text
/secretary
```

AI 秘書からヒアリングが始まります。質問は **選択肢から選ぶ形式** で出るので、`↑` `↓` キーで選んで Enter を押します（当てはまるものがなければ `Type something.` を選んで自由に入力できます）。

| 順番 | 質問 | 回答例（個人で Web 制作をしている場合） |
|---|---|---|
| 1 | あなたの主な役割や職業 | `フリーランス` |
| 2 | 典型的な 1 日の流れ | `午前に集中作業・午後に打合せ` |
| 3 | 管理したい領域（複数選択） | `TODO`・`プロジェクト管理`・`アイデア` |
| 4 | 使う言語 | `日本語` |
| 5 | `.secretary/` を作る場所 | `カレントディレクトリ`（今開いているフォルダ） |
| 6 | フォルダ構成の確認 | `OK（この構成で生成）` |

> [!TIP]
> **複数選択の質問（3 番）の操作** — 番号キーを押すと `[✔]` が付いたり外れたりします。選び終わったら `Tab` で次の質問へ進み、最後の **Submit** 画面で `Submit answers` を選びます。質問はタブ形式で並んでおり、`Tab` / `Shift + Tab` で行き来できます。

途中で、テンプレートを読み込むコマンドや `.secretary/` を作るコマンドの **許可ダイアログ** が出ます（Manual モードの場合）。実行内容が `.secretary` フォルダ内の作成であることを確認して `Yes` を選んでください。

完了の目安

- `.secretary/` が生成される（`CLAUDE.md`・`inbox/`・`reviews/`・`todos/` などが入っている）
- 業務カテゴリや inbox が確認できる

> [!NOTE]
> `.secretary/CLAUDE.md` には、オンボーディングで答えた内容（役割・1 日の流れ・使う言語など）と、管理モードのルールが書き込まれます。AI 秘書はこのファイルを読んで動きます。


### 6. 自分仕様に育てる

カテゴリを追加します。

```text
カテゴリ追加 顧客対応
```

新しいフォルダが作られ、`.secretary/CLAUDE.md` のフォルダ一覧にも追記されます（フォルダ名は `customer-support` のように英語になることがあります）。

`.secretary/` を開き、構造を確認します。

- カテゴリごとのフォルダ
- `inbox/`
- `reviews/`
- タスクやメモの保存先

続けて、業務ルールを追記します。書く場所は **作業フォルダ直下の `CLAUDE.md`**（`.secretary/` と同じ階層）です。Claude Code は起動時にこの `CLAUDE.md` を自動で読み込むので、`/secretary` を呼び出したときにもルールが反映されます。Session 2 の **`講義サンプル`** で編集した `CLAUDE.md` をコピーして使っても、新規に作っても構いません。

```markdown
# AI 秘書ルール

- タスクは「高・中・低」の優先度で分類する
- 顧客名は実名ではなく「クライアントA」のように匿名化する
- 週次レビューでは、完了・未完了・来週の重点を分ける
```

### 7. 代替ワーク — プラグインが使えない場合

ネットワークや端末設定により cc-secretary が使えない場合は、手動版 AI 秘書を作ります。これは §1「素の Claude Code との違い」で示した「秘書ワークの土台を自分で設計する」アプローチを、最小構成で再現するものです。

```text
このフォルダに manual-secretary というフォルダを作ってください。
中に以下のファイルを作成してください。

- tasks.md
- inbox.md
- weekly-review.md
- rules.md

tasks.md には「今日」「今週」「いつか」の3区分を作ってください。
inbox.md はメモ置き場にしてください。
weekly-review.md は週次振り返り用のテンプレートにしてください。
rules.md には秘書運用ルールを書いてください。
```

完了の目安

- `manual-secretary/` が作成される
- プラグインなしでも秘書ワークを継続できる

**Part B — Lark CLI**（§8〜§14）

### 8. Lark CLI とは

> [!IMPORTANT]
> - **§1〜§7 で cc-secretary（AI 秘書）のインストールと基本操作が終わっていることを確認してから** 進めてください。Lark CLI は **cc-secretary の後** にインストールします。
> - Lark CLI はあなたの Lark 権限の範囲で API を実行します。**`--as user`** で本人認証し、他人のデータを無断操作しないでください。
> - 機密情報は Session 2 と同様、入力前に匿名化してください。

[Lark CLI](https://github.com/larksuite/cli)（`lark-cli`）は、Lark の **公式 CLI ツール** です。人間がターミナルから直接使うだけでなく、**Claude Code などの AI Agent** が Lark の各種 API を安全に呼び出すために設計されています。

![Claude Code が自然言語の依頼を受け、Lark CLI を実行して Lark クラウド上のカレンダー、タスク、Docs、Base などの業務データを扱う流れ](/assets/images/training/session3/lark-cli-cloud-flow.svg)

| 特徴 | 内容 |
|---|---|
| カバー範囲 | メッセンジャー、Docs、Base、Sheets、カレンダー、メール、タスク、会議など **18 業務ドメイン** |
| コマンド数 | **200+** の厳選コマンド |
| AI 向け Skill | **約 30** の Agent Skill（2026 年 10 月時点で 28 個。`lark-calendar`、`lark-doc`、`lark-base` など） |
| ライセンス | MIT（`npm install` で利用開始可能） |
| 設計思想 | Agent 向けに最適化（簡潔な引数、スマートデフォルト、構造化出力） |

cc-secretary が **ローカルファイル** で秘書業務を担うのに対し、Lark CLI は **Lark クラウド上の業務データ**（予定、タスク、ドキュメント、表など）にアクセスします。講義では **Lark CLI を標準手段** として使います。

### 9. Lark CLI のインストール

#### 前提環境

| 項目 | 要件 |
|---|---|
| Node.js | `npm` / `npx` が使えること |
| Lark アカウント | Lark Suite にログインできること |

> [!NOTE]
> **Node.js が入っていない場合**
>
> ターミナルで `node -v` を実行してバージョンが表示されなければ未インストールです。
> [Node.js 公式サイト](https://nodejs.org) から **LTS 版**をインストールしてください（`npm` も同時に使えるようになります）。
> インストール後、ターミナルを再起動してから `node -v` で確認できます。

#### インストール

```bash
npx @larksuite/cli@latest install
```

このコマンドを実行すると **インストールウィザード** が始まり、§10 の設定まで続けて進みます（v1.0.98 時点）。

| 順番 | 画面に出ること | すること |
|---|---|---|
| 1 | `请选择语言 / Select language`（言語選択） | **初期選択は「中文」** です。`↓` キーで **`English`** を選んで Enter |
| 2 | `Installed globally` / `Skills installed` | 自動で進みます（CLI 本体と Agent Skills のインストール） |
| 3 | QR コードと URL（アプリ設定） | 表示された **URL をブラウザで開き**、Lark アカウントでアプリを作成します（§10-1 と同じ内容） |
| 4 | AI に Lark のデータへのアクセスを許可するかの確認 | 内容を読んで許可します |
| 5 | ユーザーログイン | ブラウザで承認します（§10-2 と同じ内容） |

> [!NOTE]
> 手順 3 で表示される URL は `open.feishu.cn`（中国版 Feishu）で、画面の一部が中国語で表示されることがあります。Lark CLI は **Feishu 側からアプリ登録を始め、Lark のアカウントを検知すると自動で Lark 用に切り替える** 仕組みです（`Detected Lark tenant, switching endpoint...` と表示されます）。URL は改変せずにそのまま開いてください。

> [!TIP]
> 途中で止めてしまった・失敗した場合は、§10 のコマンドを個別に実行すれば続きから設定できます。

#### Agent Skill のインストール（Claude Code 連携用）

Claude Code から Lark を操作するための **Agent Skills** は、上のウィザード（手順 2）で **自動的にインストール** されます。ウィザードで `Failed to install skills` と表示された場合だけ、次のコマンドで手動インストールしてください。

```bash
npx skills add larksuite/cli -y -g
```

> [!NOTE]
> `skills` は、**Skill**（Session 2 で触れた、Claude に追加能力を持たせる仕組み）を Claude Code などの AI ツールにまとめてインストールするための CLI です（Claude Code の Skill は、複数の AI ツールで共通に使える [Agent Skills](https://agentskills.io) というオープン標準に沿っています）。`npx skills ...` で都度実行できるため事前インストールは不要で、ここでは GitHub リポジトリ `larksuite/cli` が同梱する Skill 群（`lark-calendar`、`lark-doc` など）を取得しています。cc-secretary が `/plugin` で配布されるのに対し、Lark CLI の Skill はこの `skills add` で配布される、と覚えてください。

`-g` はグローバル配置（どのプロジェクトからも参照可）です。講義用プロジェクトだけに置く場合は `-g` を外し、プロジェクト直下で実行してください。

#### インストール確認

```bash
lark-cli --version
```

バージョンが表示されれば OK です。

### 10. Lark CLI の設定

インストール後、**アプリ作成・認証情報の登録** → **ユーザー OAuth ログイン** の 2 段階が必要です。§9 のインストールウィザードを最後まで進めた場合は両方とも済んでいるので、**§10-3 で確認だけ** してください。

#### 10-1. アプリ作成・認証情報の登録（初回のみ）

**カスタムアプリを持っていない場合（新規作成）**

```bash
lark-cli config init --new
```

コマンドを実行するとブラウザが開き、アプリ作成〜認証情報の取得まで案内されます。完了すると `app_id` / `app_secret` がローカルに保存されます。

**既存のカスタムアプリがある場合（App ID / App Secret を手元に用意）**

```bash
lark-cli config init
```

対話形式でモードを選択するプロンプトが表示されます。`Enter app credentials yourself` を選び、プラットフォームは **Lark** を選んで、既存アプリの `App ID` と `App Secret` を入力して登録してください。

> 手順の詳細は [公式 Quick Start](https://github.com/larksuite/cli#installation--quick-start) を参照してください。

#### 10-2. ユーザーログイン（OAuth）

自分の Lark データにアクセスするため、ユーザー本人としてログインします。

```bash
lark-cli auth login --recommend
```

`--recommend` は、**すべての業務ドメインの権限をまとめて要求** するオプションです（`--domain all` と同じ。オプションを何も付けない `auth login` も同じ動きになります）。講義ではこれを使うのが簡単です。業務で使うときは、`--domain` で必要なドメインだけに絞ると安全です。

その他のログイン例

```bash
# 対話式（ドメイン・権限を TUI で選択）
lark-cli auth login

# ドメインを絞る（カレンダーとタスクだけ、など）
lark-cli auth login --domain calendar,task

# 特定スコープを指定
lark-cli auth login --scope "calendar:calendar:read"
```

#### 10-3. ログイン状態の確認

```bash
lark-cli auth status
```

現在のログインユーザーと付与済みスコープが表示されれば成功です。

#### 認証コマンド一覧

| コマンド | 動作 |
|---|---|
| `auth login` | OAuth ログイン（スコープ付与） |
| `auth logout` | ログアウト・認証情報削除 |
| `auth status` | ログイン状態・スコープ確認 |
| `auth check` | 特定スコープの有無確認（0=OK、1=不足） |
| `auth scopes` | アプリで利用可能なスコープ一覧 |
| `auth list` | 認証済みユーザー一覧 |
| `auth qrcode` | 認証用 URL の QR コードを表示（スマホで承認したいとき） |

#### ユーザー / Bot の使い分け

| 種別 | フラグ | 用途 |
|---|---|---|
| ユーザー | `--as user` | 自分のカレンダー、Docs、タスクなど |
| アプリ（Bot） | `--as bot` | アプリ名義のメッセージ送信など |

講義では **個人の Lark データ** を扱うため、基本は **`--as user`** です。`--as` を省略すると設定やログイン状態から自動で決まり、ログイン前などは **Bot 名義** になることがあるため、講義では明示してください。

#### 3 層のコマンド体系

Lark CLI は用途に応じて 3 段階の粒度で API を呼び出せます。

| 層 | 形式 | 特徴 |
|---|---|---|
| 1. Shortcuts | `+` プレフィックス（例: `calendar +agenda`） | 人間・AI 向け。スマートデフォルト、表形式出力 |
| 2. API Commands | `lark-cli calendar calendars list` など | OAPI メタデータから自動生成。100+ コマンド |
| 3. Raw API | `lark-cli api GET /open-apis/...` | 2500+ API を直接呼び出し |

講義ではまず **Shortcuts（`+` コマンド）** から慣れるのがおすすめです。

### 13. Claude Code から Lark CLI を使う

講義のゴールは「ターミナルで打つ」だけでなく、**Claude Code が Lark CLI を実行して業務を進める** ことです。

#### 連携の流れ

1. §1〜§7 で **cc-secretary（AI 秘書）を先に完了** する
2. §9 のインストールウィザードで `lark-cli` と Agent Skills をインストール（そのままアプリ設定・ログインまで進む）
3. ウィザードを途中でやめた場合は、§10 で `config init --new`（新規アプリ）または `config init`（既存アプリ）と `auth login --recommend` を完了
4. 自然言語で依頼 → Claude が `lark-cli` コマンドまたは Skill を実行

> [!NOTE]
> Claude Code に設定を任せる場合は、バックグラウンドで `lark-cli config init --new` を実行し、表示された **認証 URL をそのまま** ブラウザで開いてもらう運用も可能です（[公式 AI Agent Quick Start](https://github.com/larksuite/cli#quick-start-ai-agent) と同じ手順）。URL は改変せずコピーしてください。OAuth ログイン（`auth login --recommend`）も同様です。

#### Claude Code への依頼例

```text
lark-cli calendar +agenda を実行して、今日の予定を表形式で要約してください。
```

```text
Lark の未完了タスクを確認し、期限が近いものを3件ピックアップしてください。
```

```text
「Claude Code 講義メモ」というタイトルで Lark Docs を新規作成し、
本日の学習要点を3行で書き込んでください。
```

完了の目安

- `lark-cli auth status` が成功する
- `calendar +agenda` で予定が表示される（または Claude 経由で同等の結果が得られる）
- Docs または Base の操作を 1 回以上体験できる

> [!CAUTION]
> Lark CLI は AI Agent から自動実行されるため、プロンプトインジェクション等のリスクがあります。公式 README の [Security](https://github.com/larksuite/cli#security--risk-warnings-read-before-use) を読み、デフォルトのセキュリティ設定を安易に緩めないでください。

### 14. AI 秘書と Lark CLI の使い分け

§1 の比較表が **「素の Claude Code」vs「cc-secretary」** という *導入するかどうか* の判断材料だったのに対し、ここでは **「cc-secretary」vs「Lark CLI」** という *どちらの道具で何をやるか* の使い分けを整理します。

| 用途 | AI 秘書（cc-secretary） | Lark CLI |
|---|---|---|
| タスク・メモの日常的な書き留め | ◎ `.secretary/` に蓄積 | △ Lark タスクと連携する場合 |
| 週次振り返り・ローカル整理 | ◎ | △ |
| カレンダー・会議 | △ | ◎ `calendar +agenda` など |
| チーム共有の Docs / Base | △ | ◎ |
| オフライン・ローカル優先 | ◎ | × API 必須 |

両方を併用する例 朝は `lark-cli calendar +agenda` で今日の予定を確認し、作業中のメモは AI 秘書の inbox に入れ、週末に `週次レビュー` と Lark のタスク一覧を照らし合わせる。

## 付録

### A. `/config` コマンドで設定を対話的に変更する

ターミナルで `/config` と入力すると、Claude Code の設定を対話メニュー（**Config** タブ）から変更できます。表示されるのはよく使う個人設定だけで、すべての設定項目ではありません（[設定 公式ドキュメント](https://code.claude.com/docs/ja/settings)）。主な設定項目の例を以下に示します（バージョンにより表示名・並びが変わることがあります）。

| 設定項目 | 内容 |
|---|---|
| **Auto-compact** | コンテキストが上限に近づいたとき自動で圧縮する |
| **Thinking mode** | Extended Thinking（深い推論）のオン・オフ |
| **Rewind code (checkpoints)** | ファイル編集履歴を記録し、好きな時点に巻き戻せる（§5） |
| **Default permission mode** | 起動時の権限モード（Manual / Auto など。§3） |
| **Language** | 応答言語を指定する（例：Japanese） |
| **Theme** | Dark / Light などの配色を切り替える（`/theme` でも可） |
| **Teammate mode** | 複数の Claude で分担する「エージェントチーム」の表示方法を選択する |

メニューを開かずに `/config theme=dark` のように 1 項目だけ変更することもできます（指定できる項目は `/config --help` で確認できます）。

設定は **ユーザー（全体）→ プロジェクト → ローカル** の層で管理され、ローカル設定ほど優先されます（§8 の「設定の優先順位」と同じ仕組みです）。

> **参考記事**
>
> [Claude Code の /config で設定できること全31項目を調査してみた（Qiita）](https://qiita.com/suikyo2023/items/dbe53fbff5d2f52070a8)
>
> バイナリ解析により全設定項目を網羅した詳細な調査記事です。v2.1.138 時点の情報のため、現行版（v2.1.310）とは項目が異なる場合があります。最新の設定一覧は公式の [設定リファレンス](https://code.claude.com/docs/ja/settings-reference) を参照してください。

### B. ステータスライン表示ツール：cat-claude-statusline

ターミナル下部にステータスラインを表示し、以下の情報をリアルタイムで確認できるツールです

- **コンテキスト使用率**（`/context` を打たなくても常に見える）
- **サブスクリプションのレート制限**（5 時間・1 週間単位の残量）

コンテキストを手動で管理している方に特におすすめです。

> [!NOTE]
> 外部ツールを入れなくても、公式機能で同じ情報を確認できます。
>
> - **`/usage`** — プランの使用量（5 時間・1 週間の枠）をその場で表示
> - **`/statusline`** — ステータスラインを自分で設定する公式コマンド。「コンテキスト使用率とレート制限を表示して」のように日本語で頼むと、Claude が設定を作ってくれます（[ステータスライン公式ドキュメント](https://code.claude.com/docs/ja/statusline)）

> **導入方法**
>
> Claude Code に以下の URL を伝えてインストールを依頼するだけです
>
> [https://github.com/ai-ken-git/cat-claude-statusline](https://github.com/ai-ken-git/cat-claude-statusline)
>
> 例：「このページの手順に従って cat-claude-statusline をインストールしてください」

## トラブルシューティング

### Claude Code 全般

インストール・サインインで困ったときは **事前準備 §①** と [インストールのトラブルシューティング（日本語）](https://code.claude.com/docs/ja/troubleshoot-install) を参照してください。

| 症状 | 原因候補 | 対応 |
|---|---|---|
| 許可ダイアログで迷う | 操作内容が理解できていない | `No` を選んで質問する |
| 許可ダイアログが出ずに編集される | Auto モード（`⏵⏵ auto mode on`）で動いている | `Shift + Tab` で Manual モードに切り替える。`講義サンプル` フォルダを開いているか確認する |
| Plan モードにならない | `Shift + Tab` の回数がずれている | 画面下部が `⏸ plan mode on` になるまで押す、または `/plan` を使う |
| ファイルが更新・作成されない | 依頼文に「保存して」がない | 依頼文を具体化する |
| 内容が期待と違う | 編集前確認が不足 | 「まだ編集せず、改善案だけ出して」と戻る |
| 返答が鈍くなる | コンテキストが満杯 | `/context` → `/compact` または `/clear` |
| 別フォルダで作業している | エディターで開いているフォルダが違う | エディターで **`講義サンプル` フォルダ** を開き直してから再開 |
| `claude` を起動したらすぐ終了した | フォルダの信頼確認で `No, exit`（初期選択）のまま Enter を押した | もう一度 `claude` を起動し、`↓` で `Yes, I trust this folder` を選んで Enter |

### AI 秘書 / Lark CLI

| 症状 | 対応 |
|---|---|
| `/plugin` が使えない | `claude --version` でバージョン確認し、古ければ `claude update` で更新 |
| プラグインを導入できない | §7 の手動版 AI 秘書に切り替える |
| `/secretary` が認識されない | `/reload-plugins` を実行。それでもダメなら `/exit` → `claude` で再起動 |
| `.secretary/` が見つからない | 作業フォルダを確認する |
| 実名を入れてしまった | すぐに匿名化して保存し直す |
| インストール画面が中国語になった | 最初の言語選択で `English` を選ぶ（初期選択は「中文」）。やり直すときは `npx @larksuite/cli@latest install` を再実行 |
| `Failed to install skills` と表示された | `npx skills add larksuite/cli -y -g` を実行 |
| `lark-cli: command not found` | `npx @larksuite/cli@latest install` を再実行 |
| Lark で権限エラー | `lark-cli auth login --recommend` を再実行 |
| Lark の操作が失敗する | `lark-cli auth status` と `--as user` を確認 |
| `config init` が進まない | 表示 URL を改変せずブラウザで開く |
