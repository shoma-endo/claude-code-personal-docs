## 冒頭の挨拶（つかみ）

> 最初のひとこと。緊張をほぐし、ゴールと進め方を 1 分で。読み上げても、要点だけ拾ってもOK。

- **歓迎** — 「本日はお集まりいただきありがとうございます」
- **名乗り** — 名前／普段の業務をひとことで
- **会場の温度感（挙手で軽く）** — 「Claude Code、**ほぼ初めて**の方？」→「**ときどき触る**方？」→「**日常的に使っている**方？」
  - 初心者が多い → 用語をかみ砕き・デモ多めでゆっくり／経験者が多い → 要点は早めに進めて**質疑や応用を厚く**
- **今日のゴール** — 「“答えるだけの AI”ではなく、**調べて・書いて・保存までやってくれる「動く AI」（Claude Code）を、自分の仕事の道具にする**」
- **進め方** — 3 セッション構成／**見るだけでなく実際に手を動かす**（ハンズオン中心）
- **安心材料** — 失敗してOK・**元に戻せる仕組みがある**／分からなければその場で気軽に質問を
- **環境の確認** — 事前準備（インストール・エディタ・ターミナル）が済んでいるか軽く確認
- **入り** — 「では“答える AI”と“動く AI”の違いから始めます」（→ Session 1）

## トークスクリプト（話す順番・要点）

> 詳細台本ではなく **話す順番と要点のメモ**。基本は画面（デモ＋受講者ページ）を出しながら、「次に何を話す／見せるか」を思い出す用。詰まったら要点だけ言って次へ。【ワーク】= 受講者が手を動かすところ。

### Session 1（20分・概念のみ）

1. **つかみ** — 今日のゴール＝「“動く AI”を仕事の道具にする」。Session 1 は概念だけ・手は動かさない
2. **答える→動く（§1）** — 従来＝答えて終わり／エージェント＝調べて・書いて・保存までやる。表 1 枚で
3. **従来型 vs エージェント（§2-3）** — 比較表で対比。キーワード「自分で段取りして実行」
4. **4 観点→3 キーワード（§4）** — 自立性・連続性・実用性。たとえ：検索エンジン（答える）vs 部下（動く）
5. **Claude Code へ（§5）** — これが“動く AI”。次の Session 2 で実際に触る
6. **質疑 → Session 2 へ**

2. **Claude Code とは（§1・9分）** — CLI 前提。チャット AI との違いは要点のみ。利用形態の表は **CLI の行だけ** 説明し、Desktop・IDE 拡張・JetBrains・Web は「同じエンジンで画面が違うだけ」とひとことで済ませる

4. **権限モード・許可・停止（§3-4・15分）** — 実画面は §14 で初登場と予告

## 許可ダイアログの選択肢（読み方・受講者への説明）

受講者ページ §3 の許可ダイアログに出る英語の選択肢。講義中に読み上げて意味を説明する想定（実際に画面で初めて出るのは **§14** のファイル編集時）。

> [!IMPORTANT]
> **v2.1.283 以降、普通のフォルダでは Auto モードで起動し、許可ダイアログがほとんど出ない。** `講義サンプル` は `.claude/settings.json` の `"defaultMode": "default"` で Manual 起動にしてある。§14 でダイアログが出ない受講者は、①`講義サンプル` 以外のフォルダを開いている、②`Shift + Tab` で Auto に切り替えてしまった、のどちらかが多い（画面下部の `⏵⏵ auto mode on` で判別）。

- `Yes`（イエス）
  - 今回の操作だけ許可。基本はこれを選ぶ
- `Yes, and switch to accept edits (auto-approve file edits and common file commands) for this session`（イエス、アンド・スイッチ・トゥ・アクセプト・エディッツ・フォー・ディス・セッション）
  - このセッション中は Accept edits モードに切り替え、以後の編集を確認なしで許可（ダイアログが出なくなる）。頻出操作に慣れてから検討。末尾の `(shift+tab)` は「Shift+Tab でも同じ切り替えができる」という意味
- `No`（ノー）
  - 拒否。`Tab` でコメント欄を開くと「拒否して別の指示を出す」ことができる（版によっては `No, and tell Claude what to do differently`＝ノー、アンド・テル・クロード・ホワット・トゥ・ドゥ・ディファレントリー と表示）
- `Yes, and don't ask again`（イエス、アンド・ドント・アスク・アゲイン）
  - コマンド実行時に出る。次回以降も同じコマンドは聞かない（`.claude/settings.local.json` に保存）。講義中は選ばない
- `Yes, and switch to auto mode`（イエス、アンド・スイッチ・トゥ・オート・モード）
  - コマンド実行時に出る。許可して Auto モードに切り替える。講義中は選ばない

> [!NOTE]
> 「セッション中」= `claude` を起動してから終了（`/exit`）するまで。終了すると許可はリセットされ、次回起動時にまた確認が出ます。

> [!WARNING]
> **フォルダの信頼確認に注意** — 新しいフォルダで初めて `claude` を起動すると「Quick safety check: Is this a project you created or one you trust?」が出る。**初期選択が `No, exit`** なので、Enter 連打の受講者は終了してしまう。「`↓` で `Yes, I trust this folder` を選んでから Enter」と口頭で必ず伝える（事前準備 ③・講義サンプルを開いた直後の 2 回）。

## 想定 Q&A（受講者から来そうな質問）

質疑応答（Session 2 進行表の最終枠・10 分）や実習中に出やすい質問と、講師の回答例。**節番号は受講者ページの節**を指す。回答は要点のみ——詳細は該当節へ誘導する。

### 料金・プラン

| 質問 | 回答（要点） |
|---|---|
| お金はかかる？ | 本講義は **Claude Pro プラン以上** のサブスクが前提。Anthropic 公式のトークン単価表（API 課金）は別の仕組みで、Claude Code の個人利用には当てはまらない。 |
| 使いすぎると止まる？ | レート制限あり（5 時間・1 週間の枠）。**`/usage`** で残量を確認。`/compact`・`/clear` で会話を整理すると消費を抑えられる。常時表示は **付録 B**。 |
| Fable は使える？ | `/model fable` で選べるが、プランによっては **追加の使用クレジット（有料）** が必要。一覧に「Requires usage credits」と出たら講義中は選ばない。 |
| 無料で試せる？ | 無料枠は限定的。本講義の手順は Pro 以上を想定。 |

### 安全・プライバシー（§2）

| 質問 | 回答（要点） |
|---|---|
| 入力内容は学習に使われる？外に出る？ | 実行は手元の PC だが、**プロンプトや読み込んだファイルの内容は Anthropic に送信**される。機密情報は入れない（§2）。 |
| 勝手にファイルを消さない？ | Manual モードなら編集の前に **許可ダイアログ** が出る（§3）。プロンプトごとに **チェックポイント** が作られ `Esc` 2 回／`/rewind` で戻せる。基本は `Yes`、不安なら `No`。 |
| Auto モードは安全？ | 別の AI（分類器）が危険な操作（外部送信・大量削除など）をブロックするが、公式も「安全を保証しない」と明記。慣れるまでは Manual 推奨（§3）。 |
| 会社の機密ファイルで使っていい？ | 講義中は **ダミーのみ**。実務利用は社内ルールに従い、ファイル名・コミットに機密を含めない。 |

### 講義サンプル（今回の仕様）

| 質問 | 回答（要点） |
|---|---|

## サンプルデータ（開発・講師環境）

```bash
# エディターで開く
docs/training/claude-code-personal/sample-data

# またはホームへコピー
cp -r docs/training/claude-code-personal/sample-data ~/claude-code-personal
```
